# 稳定需求

从 [V4.3](<../STRM Generator Go.md>) 提取，并将本地文件安全和证据边界明确化。全部为 TARGET；CURRENT 见 [架构](architecture.md)。

| ID | 要求与验收含义 |
|---|---|
| R-01 | 使用 OpenList API，处理传输状态、JSON 外层 code、分页及缺失字段；失败不是空目录。只使用已有内容哈希，不下载媒体补算。 |
| R-02 | 生成版本 1 UTF-8 STRM，推荐无 BOM／LF；标记各一次；有效 HTTP(S) URL；总长 ≤65,536 字节；SHA-1 为40位十六进制，输出小写；Size 为0..9223372036854775807整数；缺失／无效字段省略，不写 Modified。 |
| R-03 | `public_url + /d/ + 远程绝对路径` 构造稳定 URL，路径逐段编码，保留目录分隔；不使用 get.raw_url、sign、签名查询参数。public_url 的现有路径前缀不能丢失；不允许凭拼接产生主机替换或查询注入。 |
| R-04 | 镜像相对目录，媒体扩展名替换为 .strm。输出根按 SW-1..SW-6 单写者独占且不重叠；同目标冲突（如 A.mkv/A.mp4）明确失败，不任意选择。拒绝穿越、非法名称和符号链接逃逸；不以 basename 掩盖异常路径。 |
| R-05 | 使用下表比较现有 STRM。无变化不改字节／mtime；SHA-1 相同但 Size 异常时跳过并记录。不能用路径／URL 的哈希冒充内容哈希。 |
| R-06 | 在 SW-1..SW-6 前提下，同目录临时文件写完后原子替换，失败保留可证明的旧／新完整文件；SQLite 只存归属、路径、完整成功轮次、连续缺失计数。文件与库并非一笔事务，崩溃窗口须安全恢复，不允许由孤儿记录推导删除权限。不承诺对绕过单写者边界的任意并发写入提供按 inode 条件替换／删除。 |
| R-07 | 新增／移动的新路径写入；旧路径仅按安全删除规则清理。无归属既有文件不自动认领／覆盖／删除。恢复／丢失数据库时默认保留文件，重建策略须显式设计与验收。 |
| R-08 | 删除前连续两次完整成功对账缺失，且再确认不存在；只删除可靠归属且仍在输出根内的文件。失败轮不增加缺失计数、不执行清理；远端再出现重置连续缺失。若清理确认失败则保留。 |
| R-09 | 单轮内远端变化由下轮修正，不要求每次写入前再次查询或远端版本锁。获取、比较、写入与清理失败均可观测，不宣称事务快照。 |
| R-10 | 目标 CLI 为 sync、sync --dry-run、serve；dry-run 不创建／修改输出、数据库、轮次或缺失计数（可写脱敏日志）；serve 与手动共享同一互斥入口。错误有非零退出码和摘要。 |
| R-11 | 同一输出范围跨进程单轮互斥，并满足 SW-1..SW-6 的本地单写者前提；目录读取工作池、队列、HTTP响应和数据库处理有界；不能为全库每个文件创建 goroutine／保存完整对象。停止不使不完整轮成为成功轮。 |
| R-12 | token 来自环境变量；不输出凭证、完整签名 URL 或私有完整路径。运行时错误不泄密。部署目标 Linux amd64／arm64；512 MB／规模必须带环境和实际测量数据。 |

## 本地单写者安全合同（SW，2026-10-18 A 修订）

用户授权 A 限制外部写者。本节显式收窄本地并发威胁模型，不改原始 V4.3 方案、远端变化规则、STRM 协议或 SQLite 持久事实边界。不是已交付能力声明；CURRENT 与未完成项见架构／TASK。

- **SW-1 写入主体与生命周期：** 输出根、其子目录／目标／暂存对象、SQLite 及其 sidecar 和锁资源只允许受信任的生成器写入；生成器多进程通过同一锁串行化。限制贯穿正常轮、轮次之间、取消、进程退出到恢复重启，不仅是某个 syscall 窗口。外部程序不得原地写文件或创建／删除／替换目录项，也不得经硬链接、其他可写挂载或别名绕过限制。远端 OpenList 内容变化不受此限制，仍按 R-09 最终一致性处理。
- **SW-2 部署者责任：** 推荐专用生成器 UID；消费者用不同 UID 或有效只读挂载访问。输出目录、文件及可替换它们的父目录不得给消费者写权限；数据库、锁目录和锁文件也要受保护。所有访问相同输出的生成器须看到同一锁文件对象；共享输出却使用各自容器私有的 /tmp 锁不属于支持部署。仅 chmod 0700 不能隔离同 UID，现有 advisory flock 不阻止不参与协议的进程；应用启动检查不等于证明全系统不存在外部写者。不在运行时自动 chmod／chown、改 ACL／挂载或停止外部服务。
- **SW-3 程序内已知条件检查：** 复用绑定目录和文件句柄，在恢复／创建／更新之前检查将使用的输出根、目标父目录，以及将修改的已拥有普通文件：属主须为有效运行 UID，且不可 group／other 写。还须核对生成器使用的 DB 父目录／已有状态文件及锁资源的同类条件；dry-run 只读检查，不因校验创建输出或 sidecar。已绑定路径／祖先的防替换边界继续保留；祖先权限、ACL、身份／挂载隔离与锁命名空间仍由部署者保证，不伪称已完整审计。检测到已知不满足、无法取得必要属性或异常对象时，受影响 source 非零失败且不推进完整 round；在该对象上不做恢复／发布／清理。不得全库预加载或为检查新建探测文件。
- **SW-4 仍保证的安全：** 既有未归属文件、无 DB／无可信归属、启动时不明残留和可观测类型／路径冲突不自动认领／覆盖／删除。OS 属主、名字、合法协议或内容哈希不等于应用归属。生成器自身的写入／同步／关闭／交换／目录同步／DB 失败、信号中断和多次重启仍须安全；不明恢复证据保留，不能因第一次报冲突而在后续运行重新获得写权限。dry-run 零写、不完整轮不推进、路径边界与有界工作均不降低。
- **SW-5 不保证与维护：** 绕过边界的同 UID／root／特权进程、在线 ACL／挂载／权限变化及不受约束的外部名字／内容替换，不属于原子安全保证。程序发现异常仍保守失败，但不承诺能发现或逆转每次违规。维护应先停止全部生成器并保留 DB／输出／残留；修改已拥有文件、残留或状态后不得直接带旧 ownership 继续，当前未提供通用原地再认领功能。未验证恢复须保持冲突，不能建议盲删暂存或伪造归属；重新生成／迁移须使用明确隔离的新空输出与新状态，并由管理员确认。
- **SW-6 验收分层：** 在专用隔离夹具中证明不同身份／只读消费者能读而不能创建、改写、改名或删除目标及暂存；权限不合规输入应在相应修改前失败。证明相同锁资源下多生成器互斥、正常更新及无外部写者的崩溃／重启／回滚／清理仍满足 T4。既有任意外部写者反例保留为旧合同失败或越界故障注入，不能改写为通过；其不再是对任意 syscall 间隙绝对安全的验收要求。旧测试的具体调整须由 B 明列映射和替代覆盖，不得批量删除或把 NOT RUN 当 PASS。

SW-3 不要求 dry-run 的缺失输出／数据库先被创建；检查可安全绑定的最近既有父目录与已存在对象，并保留“预计创建”的原有预览语义。真实创建时对新建对象复核同类条件。可识别的 legacy／不明恢复冲突即使在修改部署权限后也不会自动洗成可信；只能从可信生成器写入来源、现有归属和完整恢复证据论证正常恢复，不能仅凭设置了单写者前提忽略冲突。

## 比较规则

以下插件行为以已有历史指纹、必要主媒体流和原生地址匹配为前提；缺主流、原生地址不匹配、首次接管规则仍由插件负责。

| 输入变化 | 生成器目标行为 | 插件已核对规则 |
|---|---|---|
| URL 变化（其他任意） | 更新 | 需要原生探测 |
| URL 相同，两侧有效 SHA-1 相同 | 跳过；Size 不同记录异常 | 忽略 Size，复用 |
| URL 相同，两侧有效 SHA-1 不同 | 更新 | 需要探测 |
| URL 相同，SHA-1 不可比，两侧有效 Size 不同 | 更新；新文件只使用当前可用元数据 | 需要探测 |
| URL 相同，SHA-1 不可比，两侧有效 Size 相同 | 跳过；不声称哈希验证了内容 | 复用 |
| URL 相同，SHA-1 不可比，Size 信息不足 | 不据此推断变化；记录限制 | 信息不足不凭空探测 |
| 仅 Modified 变化 | 跳过 | 不参与比较 |

跳过不重新序列化已有文件。当前信息缺失不伪造零 Size，不把一个已确认旧版本的哈希拼到新 URL／新 Size 上。可选元数据补齐若需要改变以上跳过行为，必须先明确合同，不作为环境准备阶段的隐含实现。

## 完整轮与缺失确认

完整成功轮要求该源所有必要目录与分页成功，响应结构可判读、遍历结束，且本轮必要处理成功。保守以单个 source 为轮次提交边界；一个 source 失败不推进它的缺失依据。是否继续其他独立 source 可由 Task 明确，但不得借另一源成功给失败源清理。

两次计数不能来自 dry-run、失败、取消或不完整分页。删除前再次通过可证明权威的远端检查确认不存在；HTTP 404 或 JSON code 的含义须对目标 OpenList／驱动实证，不能把所有 get 错误视为不存在。可采用成功刷新并完整读取父目录后的精确名称确认。缺失／离线存储或权限被撤销时必须保留旧 STRM。
