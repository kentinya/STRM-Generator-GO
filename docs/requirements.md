# 稳定需求

已交付需求版本为 V4.4，本文件定义业务规则、本地文件安全和证据边界。
自定义扩展名增量需求已由 Slice 5 验收并 PASS / CLOSED，见下节与
[A 最终审查](../SLICE.md#closure-packet)；当前无活动实施任务，历史入口见 [TASK](../TASK.md)。

| ID | 要求与验收含义 |
|---|---|
| R-01 | 使用 OpenList API，处理传输状态、JSON 外层 code、分页及缺失字段；列表失败不是空目录，所有列表请求均使用 refresh:false。目标 Get 的缺失语义按下节用户简化规则处理。只使用已有内容哈希，不下载媒体补算。 |
| R-02 | 生成版本 1 UTF-8 STRM，推荐无 BOM／LF；标记各一次；有效 HTTP(S) URL；总长 ≤65,536 字节；SHA-1 为40位十六进制，输出小写；Size 为0..9223372036854775807整数；缺失／无效字段省略，不写 Modified。 |
| R-03 | `public_url + /d/ + 远程绝对路径` 构造稳定 URL，路径逐段编码，保留目录分隔；不使用 get.raw_url、sign、签名查询参数。public_url 的现有路径前缀不能丢失；不允许凭拼接产生主机替换或查询注入。 |
| R-04 | 镜像相对目录，媒体扩展名替换为 .strm。输出根按 SW-1..SW-6 的正常单写者使用方式部署且不重叠；同目标冲突（如 A.mkv/A.mp4）明确失败，不任意选择。拒绝穿越、非法名称和符号链接逃逸；不以 basename 掩盖异常路径。 |
| R-05 | 使用下表比较现有 STRM。无变化不改字节／mtime；SHA-1 相同但 Size 异常时跳过并记录。不能用路径／URL 的哈希冒充内容哈希。 |
| R-06 | 在 SW-1..SW-6 的支持边界内，同目录临时文件写完后原子替换，失败保留完整的旧／新文件及必要恢复依据，正常中断后可重试收敛；SQLite 只存归属、路径、完整成功轮次、连续缺失计数。文件与库并非一笔事务，崩溃窗口须安全恢复，不允许由孤儿记录推导删除权限。不承诺对绕过单写者边界的任意并发写入提供按 inode 条件替换／删除。 |
| R-07 | 新增／移动的新路径写入；旧路径仅按安全删除规则清理。无归属既有文件不自动认领／覆盖／删除。恢复／丢失数据库时默认保留文件，重建策略须显式设计与验收。 |
| R-08 | 配置源根未成功读取为目录时保留，不增加缺失次数；源根可读取时，目标 Get 未读到即按缺失处理，不区分其他原因造成的相同响应。至少连续三次完整轮缺失及删除前当前相同 Get 判定后，只删除可靠归属、精确映射且仍在输出根内的 regular STRM。再出现清零；整轮取消、列表分页不完整或本地必要处理失败不推进计数。清理阶段本地失败停止后续删除并安全恢复。扩展名排除的增量资格见 R-13。 |
| R-09 | 单轮内远端变化由下轮修正，不要求每次写入前再次查询或远端版本锁。获取、比较、写入与清理失败均可观测，不宣称事务快照。 |
| R-10 | 目标 CLI 为 sync、sync --dry-run、serve；dry-run 不创建／修改输出、数据库、轮次或缺失计数（可写脱敏日志）；serve 与手动共享同一互斥入口。错误有非零退出码和摘要。 |
| R-11 | 同一输出范围跨进程单轮互斥，按 SW-1..SW-6 的本地单写者使用方式运行；目录读取工作池、队列、HTTP响应和数据库处理有界；不能为全库每个文件创建 goroutine／保存完整对象。停止不使不完整轮成为成功轮。 |
| R-12 | token 来自环境变量；不输出凭证、完整签名 URL 或私有完整路径。运行时错误不泄密。部署目标 Linux amd64／arm64；当前规模验收为 10000 个 STRM，记录环境、耗时与峰值 RSS，不设额外内存数值门槛。 |

## 自定义扩展名

R-13 是 Slice 5 对 V4.4 的已验收增量。以下规则与原合同含义一致；
验收结果见 [Slice 5 关闭记录](../SLICE.md#closure-packet)，实现职责见
[架构](architecture.md#自定义扩展名接入)。V4.4 历史验收不回写为当时已支持本增量。

### 输入与筛选

1. `sync.media_extensions` 是全局列表，所有 source 使用同一列表。省略时使用内置
   11 项：`.mkv`、`.mp4`、`.m4v`、`.avi`、`.mov`、`.wmv`、`.webm`、`.ts`、
   `.m2ts`、`.mpg`、`.mpeg`；旧配置无需修改。
2. 显式列表完整替换默认项，不合并。必须是非空 YAML 字符串列表；空列表、`null`、
   标量、非字符串元素、嵌套结构和空元素均拒绝，不通过隐式转换接受。
3. 每项去除首尾空白，接受一个可选前导点，其余只允许 ASCII 字母或数字；
   统一为带点的小写扩展名并去重。路径、内部空白、通配符、单独的点、多段后缀及
   `.strm`（大小写无关）均拒绝。`MKV`、`.mkv`、` .MKV ` 等价。
4. 只匹配文件名最后一个扩展名，大小写无关；目录始终遍历。`.mp4` 匹配 `Movie.MP4`，
   不匹配 `Movie.mp4.bak` 或无扩展名文件。列表只允许生成链接，不保证消费端能播放。
5. `sync`、`sync --dry-run` 和 `serve` 共用解析与筛选规则；列表按实例持有，不修改
   共享默认集合。`serve` 启动时读取配置，修改后重启生效，不热加载。
6. 配置错误在远端请求、输出／数据库准备和同步前返回退出码 `2`；诊断标明字段，
   不回显原始配置值、凭证或私有路径。

### 排除、恢复与冲突

从列表移除扩展名后，对应源文件停止生成／更新，已有可靠归属 STRM 按不再需要的
输出进入正常计数／清理，即使源文件仍存在且 Get 成功，也不保留或清零。
删除自定义配置回到默认列表时同样适用，不设额外保留开关。

沿用 `cleanup.enabled` 与 `sync.mirror`，清理默认关闭，关闭时不新增计数或删除。
开启后复用原计数，每个完整成功轮至多增加一次；默认／最低阈值为 `3`。
删除只消费已提交证据，并重新核对当前源根、当前列表／目标状态以及本地归属与边界，
不能因一次配置变更立即删除；稳定时至迟在达到阈值后的下一次成功同步收敛。

清理资格为：精确映射的源扩展名仍被当前列表排除，或扩展名仍入选但按 R-08 未读到目标。
恢复入选且源文件可读时清零并取消删除；若源仍未读到则继续原缺失流程，
仍被排除时源端重现不清零。已经清理的输出恢复入选后可重新生成，不另建计数状态。

源根门槛、完整列表、失败／取消不推进、精确远端映射、合法子路径／深度、输出边界和
可靠归属限制保持；删除还须满足 regular STRM 类型检查，目标 Get 的明确类型冲突保留。
dry-run 不改产物、原库、轮次或计数。未知精确映射的旧记录保留，不从 `.strm` 猜原扩展名。
删除失败停止后续清理，正常重跑收敛，不承诺跨文件删除回滚。

只在当前入选候选间检查同目标冲突：`Movie.mkv` 与 `Movie.flv` 都入选时应失败，
不能任意选择或推进缺失证据；被排除文件不参与新增候选冲突。
唯一入选新候选映射到已有可靠归属目标时，沿用原归属、URL 比较与精确映射更新规则，
不被旧排除记录误删；未归属既有文件不覆盖、认领或删除。

不改变 source identity、锁资源、SQLite schema、STRM V1 或 URL → SHA-1 → Size 顺序。
不提供每 source 独立列表、追加／排除双列表、通配符／正则、MIME／内容探测、
无扩展名识别、复合后缀匹配、热加载或新增 CLI 覆盖参数。

## 本地写者与最终一致性边界（SW，2026-10-18 A 澄清修订）

本节保留 2026-10-18 用户澄清后的写者与最终一致性边界，不要求 UID／mode 强制检查、
只读消费者 OS 拒写证据或任意外部残留永久冲突门槛，不增加权限安全系统。
V4.4 协议、比较规则与 SQLite 持久事实边界不变；历史验收结果见[路线图](roadmap.md)。

- **SW-1 正常使用方式：** 生成器负责写输出、暂存与状态，Jellyfin／插件等消费者只读；同一输出范围的生成器进程通过同一锁资源串行化。部署时避免其他程序同时修改这些对象。专用身份、权限隔离或只读挂载是可选部署建议，不是额外产品能力或验收门槛。
- **SW-2 不作绝对防护承诺：** 不保证同 UID、root、绕过锁或部署约束的其他写者，在任意本地操作间隙替换名字／改写内容时仍能被发现、阻止或无损逆转。不实现按 inode 条件替换／删除、全系统写者审计、强制 UID／mode 校验或自动权限修复。现有低成本检查可以保留，但不能据此扩大交付承诺。
- **SW-3 正常失败须可恢复：** 生成器自己的写入、sync、close、发布、目录同步、DB 失败、取消或进程中断仍须按既有归属与最小恢复依据安全处理；在输入稳定、存储可用、归属与路径边界有效时，后续成功同步应能收敛，不能把所有正常残留永久判冲突。首次发布后尚未登记归属的文件仍按 R-07 保留冲突，不为消除此窗口另造自动认领机制。无需每次写入前再查远端，不增加媒体版本表或独立恢复状态机。
- **SW-4 保留基线安全：** 真正未归属的既有文件、数据库丢失后无法确认归属的文件和明确路径／类型冲突，不自动认领、覆盖或删除；归属不能仅由合法 STRM、文件名或 OS 属主推导。确实无法安全解释的状态可报告冲突并保留。路径与符号链接边界、dry-run 零写、不完整轮不推进清理依据和有界工作保持不变。
- **SW-5 暂时偏差与责任：** 扫描期间变化或已拥有、可重新生成的 STRM 的可识别偏差，按既有比较规则由后续成功同步纠正，不承诺“下一次运行无条件成功”或识别任意伪造内容。普通重试或已拥有 STRM 的可识别内容变化，不一律要求新输出根／新数据库。越界外部干预不承诺无损保全其注入内容；也不能仅把同一干预事先做成静态 legacy 夹具，就重新引入被排除的绝对防护要求。
- **SW-6 验收边界：** T4 保留正常创建／更新／跳过、稳定后的重复同步、中断恢复／重启、I/O 与数据库失败、跨进程互斥、未归属文件保护和 dry-run；补齐独立有界目录枚举与正常重试收敛证据。不要求 UID／权限矩阵或不同身份消费者 OS 拒写实验。原外部写者反例如实保留为历史结果或可选诊断，由 B 显式调整映射，不改称已修复／PASS，也不靠隐藏必跑失败放行。

## 比较规则

哈希／Size 比较和不探测行以已有历史指纹、必要主媒体流和当前原生地址匹配为前提。
URL 变化行先建立地址匹配的旧基准；变更后允许 UrlChanged 或本次变化引起的
NativeUrlMismatch 触发探测，不允许用无关主流／地址缺失冒充该行。首次接管不代替比较证据。

| 输入变化 | 生成器目标行为 | 插件已核对规则 |
|---|---|---|
| URL 变化（其他任意） | 更新 | 需要原生探测 |
| URL 相同，两侧有效 SHA-1 相同 | 跳过；Size 不同记录异常 | 忽略 Size，复用 |
| URL 相同，两侧有效 SHA-1 不同 | 更新 | 需要探测 |
| URL 相同，SHA-1 不可比，两侧有效 Size 不同 | 更新；新文件只使用当前可用元数据 | 需要探测 |
| URL 相同，SHA-1 不可比，两侧有效 Size 相同 | 跳过；不声称哈希验证了内容 | 复用 |
| URL 相同，SHA-1 不可比，Size 信息不足 | 不据此推断变化；记录限制 | 信息不足不凭空探测 |
| 仅 Modified 变化 | 跳过 | 不参与比较 |

跳过不重新序列化已有文件。当前信息缺失不伪造零 Size，不把一个已确认旧版本的哈希拼到新 URL／新 Size 上。可选元数据补齐若需要改变以上跳过行为，必须先明确合同，不作为环境准备阶段的隐含实现。

## 完整轮与缺失确认

### 简化删除判定（2026-10-18 用户最终决定）

本节记录 V4.4 已接受的源根／目标 Get 判定，与[架构](architecture.md)及
[测试矩阵](development-workflow.md#测试入口)一致；Slice 5 的扩展名排除与重新入选按
[R-13](#自定义扩展名)叠加处理。旧权威列表／祖先链、强刷预算和有限例外方案从 Git 历史查看，
不作为当前要求，也不追认为新验收通过。

- **源根门槛：** 每个 source 的配置源根必须在本轮成功 Get 为目录。源根消失、Get 失败、结果无效或类型不是目录时，保留该源已有 STRM 与缺失计数，不新增缺失次数、不清理。移除 source 配置也不清扫历史归属。不再为源根增加真实驱动／虚拟视图或祖先刷新证明条件。
- **文件判定：** 源根门槛满足后，对需判断缺失的已拥有精确远端路径调用 Get；未读到目标即算一次缺失观察。目标 Get 的非成功 HTTP、应用错误（含 404／403／500）、传输／单请求超时、响应无法解析等不再按原因细分为“未知”，不再尝试辨别与真正不存在相同的响应。此规则不代表远端已被权威证明不存在；它是用户选定的业务判定。整轮 context 取消／deadline 导致同步中止时仍不提交完整轮或缺失计数，不能把中止轮凑进三次。
- **列表与出现：** 所有列表请求，包括普通扫描、确认辅助、手动与 dry-run，均显式 `refresh:false`，不提供强刷回退或单独 ListFresh 强刷入口。列表用于目录发现与生成；完整正常对账中观察到文件（含比较 skip）仍算出现。对未观察到的已有归属目标用 Get 作上述缺失判定；Get 成功读到目标时也保留并清零旧缺失。成功 Get 得到目录或其他明确类型冲突时保留并报告，不按未读到删除。父目录被删除时不再逐级刷新祖先，源根可读取且原文件 Get 未读到即可形成缺失观察。
- **计数与删除：** `cleanup.enabled` 默认 false，`sync.mirror` 默认 true；mirror false 与 cleanup true 在写入前拒绝。`cleanup.missing_confirmations` 默认 3、最低 3。只在不同完整成功轮中为每个目标增加至多一次，三次前保留；删除前消费已提交的阈值证据，重新核对当前源根可读取、目标 Get 仍未读到，以及可靠归属／精确映射／输出边界／regular STRM 类型。不再要求独立刷新列表或权威不存在证明。可在随后成功同步消费已提交证据，稳定且本地条件有效时，至迟在达到阈值后的下一次成功同步收敛。

以上明确接受：源根尚能读取而目标因权限、驱动异常、缓存等原因未能读到时，也可能累计缺失并最终触发删除。旧“目标 Get 失败一律保留”的保护被用户主动撤回，不再以识别这些原因或排除隐藏／虚拟挂载反例作为准入条件。所有列表关闭强刷仅约束本程序请求参数；缓存到期／未命中及 Get 仍可能访问后端，不承诺零网盘请求。撤下上一版强刷批次、目录证明复用、确认预算／冷却及避免分页强刷放大的新增能力与验收；原有有界资源、单轮互斥和取消退出要求保持。

### 完整轮与本地恢复边界

完整轮仍要求该源必要列表分页成功、结构可判读、遍历结束及必要本地处理成功；目标 Get 未读到是上节明确接受的缺失观察，不再作为失败轮原因。列表错误、total 改变／重复名／不完整分页、本地创建／更新冲突或 I/O／DB 失败、整轮停止不增加缺失计数，不启动该源清理。成功轮与缺失增加一致提交，同一 epoch 不重复计数，不同 source 不借用证据。正常同步确认再出现即使随后失败也可保守清零，不追加成功轮；dry-run 不持久化观察、不迁移旧库、不改轮次或计数。

关闭清理不新增缺失次数或删除；已确认再出现仍清零，其他旧计数保留。重新启用先完成当前源对账并按相同 Get 规则重核，不能只读旧计数删除。Slice 1 旧库保留归属，旧 round／created_round 不追认为缺失轮；映射可通过后续观察补齐，历史已缺失且无法可靠补齐的记录保留，不猜原扩展名、不自动认领。同轮不同媒体映射同一输出目标仍失败；合法 URL 改变按既有比较规则更新。

真正未归属文件、符号链接／输出越界／类型冲突保护不变。删除、目录 sync、DB 或进程中断的恢复仍须重核当前源根／目标 Get 与本地归属，安全完成剩余操作；本地清理错误停止该源后续删除，不保留失败轮新增证明，不承诺跨文件原子回滚。孤儿记录不授权删除未知文件，不要求人工伪造计数或盲删残留。

Task 2.1 已按本规则完成独立验收，相关接口、错误／缓存测试和真实服务工具继续保留；旧权限过滤、同码驱动失败等反例改为用户接受的判定局限，保留历史结果，不能写成已修复／安全辨别成功。整轮取消、源根保留、列表全程 refresh:false、精确路径、再出现及本地恢复继续验证；产品候选仍需相应完整 T4，真实服务与合成夹具分开报告。

## 协议与兼容

生成示例：

```text
# strm-probe-version:1
# strm-probe-sha1:aabbccddeeff0011223344556677889900112233
# strm-probe-size:10737418240
https://openlist.example.invalid/d/Movies/Sample.mkv
```

生成器输出无 BOM／LF；插件 reader 可以接受 BOM／CRLF，但不据其宽松解析输出无效值。
OpenList 的 `hash_info` 是结构化映射，`hashinfo` 是历史字符串字段；解析优先级和无效值处理
见 `internal/openlist/openlist.go` 及其测试。`raw_url`、`sign` 不写入 STRM。
稳定 `/d/` URL 必须允许对应访问；要求临时签名的挂载不满足当前前提，不自动绕过鉴权。

插件先检查必要主流及原生 URL；首次历史为空可信任已有主流。
`allowMediaProbe=false` 和探测成功后持久化指纹由插件管理，生成器不控制。
固定参考源码与外部输入见[架构](architecture.md#固定外部输入)。

## 插件决策验收矩阵

每行先建立必要主媒体流、历史指纹和匹配的原生地址，恢复并核对基准后仅改变一项。
异内容需真实 SHA-1、实际 Size 与服务字节一致；同哈希／异 Size 明示为异常元数据。
URL 变化可由 UrlChanged 或此次变化导致的 NativeUrlMismatch 触发探测，不能由无关缺主流等原因代替。
明确探测启动即可满足探测行，复用需有理由匹配的当次记录；FirstTrust、预测模型或只见任务完成不足。
原始生成文件与标注副本分别保存，副本不冒充生成器同步产物。

| ID | 单项变化（其余条件相同） | 生成器要求 | 实际插件预期 |
|---|---|---|---|
| D-01 | 输入均不变 | 跳过、字节／mtime 不变 | 明确复用／不探测 |
| D-02 | 远端仅 Modified 变化 | 跳过，不写 Modified | 明确复用／不探测 |
| D-03 | 有效 SHA-1 相同、Size 元数据不同 | 跳过并记录异常（Go 覆盖） | 忽略 Size，明确复用 |
| D-04 | URL 不变，实际内容及有效 SHA-1 改变 | 更新（目标缺 hash 时 Go 另报） | 探测 |
| D-05 | URL 改变，SHA-1／Size 不变 | 必须更新 | 探测 |
| D-06 | URL 不变，SHA-1 不可比，两侧有效 Size 不同 | 更新 | 探测 |
| D-07 | URL 不变，SHA-1 不可比，两侧有效 Size 相同 | 跳过并说明未比较哈希 | 明确复用 |
| D-08 | URL 不变，SHA-1 不可比，Size 信息不足 | 不推断变化，记录限制 | 明确不因信息不足而探测 |

源端缺少的元数据分支以 Go 回归单列；插件各行仍须观察原生实际决定。
证据中的原始文件／副本、item、source、当次日志、逐场景与最终恢复必须对应。
历史独立验收结果从[路线图](roadmap.md)追溯，普通测试通过不代表重新完成真实链路验收。
