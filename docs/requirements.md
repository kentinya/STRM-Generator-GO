## 本地写者与最终一致性边界（SW，2026-10-18 A 澄清修订）

按用户对“限制外部写者”的澄清，撤回此前追加的 UID／mode 强制检查、只读消费者 OS 拒写证据及任意外部残留永久冲突门槛。本节不要求建设权限安全系统，不改原始 V4.3 方案、比较规则、STRM 协议或 SQLite 持久事实边界，也不表示当前实现已验收通过。

- **SW-1 正常使用方式：** 生成器负责写输出、暂存与状态，Jellyfin／插件等消费者只读；同一输出范围的生成器进程通过同一锁资源串行化。部署时避免其他程序同时修改这些对象。专用身份、权限隔离或只读挂载是可选部署建议，不是本 Slice 的新增产品能力或验收门槛。
- **SW-2 不作绝对防护承诺：** 不保证同 UID、root、绕过锁或部署约束的其他写者，在任意本地操作间隙替换名字／改写内容时仍能被发现、阻止或无损逆转。不实现按 inode 条件替换／删除、全系统写者审计、强制 UID／mode 校验或自动权限修复。现有低成本检查可以保留，但不能据此扩大交付承诺。
- **SW-3 正常失败须可恢复：** 生成器自己的写入、sync、close、发布、目录同步、DB 失败、取消或进程中断仍须按既有归属与最小恢复依据安全处理；在输入稳定、存储可用、归属与路径边界有效时，后续成功同步应能收敛，不能把所有正常残留永久判冲突。首次发布后尚未登记归属的文件仍按 R-07 保留冲突，不为消除此窗口另造自动认领机制。无需每次写入前再查远端，不增加媒体版本表或独立恢复状态机。
- **SW-4 保留基线安全：** 真正未归属的既有文件、数据库丢失后无法确认归属的文件和明确路径／类型冲突，不自动认领、覆盖或删除；归属不能仅由合法 STRM、文件名或 OS 属主推导。确实无法安全解释的状态可报告冲突并保留。路径与符号链接边界、dry-run 零写、不完整轮不推进清理依据和有界工作保持不变。
- **SW-5 暂时偏差与责任：** 扫描期间变化或已拥有、可重新生成的 STRM 的可识别偏差，按既有比较规则由后续成功同步纠正，不承诺“下一次运行无条件成功”或识别任意伪造内容。普通重试或已拥有 STRM 的可识别内容变化，不一律要求新输出根／新数据库。越界外部干预不承诺无损保全其注入内容；也不能仅把同一干预事先做成静态 legacy 夹具，就重新引入被排除的绝对防护要求。
- **SW-6 验收边界：** T4 保留正常创建／更新／跳过、稳定后的重复同步、中断恢复／重启、I/O 与数据库失败、跨进程互斥、未归属文件保护和 dry-run；补齐独立有界目录枚举与正常重试收敛证据。不要求 UID／权限矩阵或不同身份消费者 OS 拒写实验。原外部写者反例如实保留为历史结果或可选诊断，由 B 显式调整映射，不改称已修复／PASS，也不靠隐藏必跑失败放行。

## 比较规则

以下插件行为以已有历史指纹、必要主媒体流和原生地址匹配为前提；缺主流、原生地址不匹配、首次接管规则仍由插件负责。

| 输入变化 | 生成器目标行为 | 插件已核对规则 |
|---|---|---|
| URL 变化（其他任意） | 更新 | 需要原生探测 |
| URL 相同，两侧有效 SHA-1 相同 | 跳过；Size 不同记录异常 | 忽略 Size，复用 |
| URL 相同，两侧有效 SHA-1 不同 | 更新 | 需要探测 |
| URL 相同，SHA-1 不可比，两侧有效 Size 不同 | 更新；新文件只使用当前可用元数据 | 需要探测 |
| URL 相同，SHA-1 不可比，两侧有效 Size 相同 | 跳过；不声称哈希验证了内容 | 复用 |
| URL 相同，SHA-1 不可比，Size 信息不足 | 不据此推断变化；记录限制 | 信息不足不凭空探测 |
| 仅 Modified 变化 | 跳过 | 不参与比较 |

跳过不重新序列化已有文件。当前信息缺失不伪造零 Size，不把一个已确认旧版本的哈希拼到新 URL／新 Size 上。可选元数据补齐若需要改变以上跳过行为，必须先明确合同，不作为环境准备阶段的隐含实现。

## 完整轮与缺失确认

以下为 2026-10-18 A 激活并按用户授权修订 Slice 2 后对 R-07／R-08／R-10 的明确约定；与 [当前合同](../SLICE.md)、[架构 TARGET](architecture.md) 和 [测试矩阵](test-matrix.md) 同步，清理实现仍未验收。原始 V4.3 不修改。

`cleanup.enabled` 默认 false，显式 true 才启用清理；`sync.mirror` 默认 true，false 只生成／更新，false 与 cleanup true 在输出／数据库变更前拒绝。`cleanup.missing_confirmations` 默认为 3，只接受整数 ≥3；提高阈值只延后清理，不提供 force 或单轮删除。关闭清理不新增缺失证明、不删除；已确认再出现仍使旧证明失效，其他既有证明保留。重新启用须先完成当前源遍历／必要处理并再次确认，不能只读旧计数直接删除。

完整成功轮要求该源所有必要目录与分页成功，响应结构可判读、遍历结束，且本轮必要处理成功。以单个 source 为证据边界，成功轮次与缺失增加一致提交；同一 epoch 不能重复计数。媒体比较 skip 仍算出现；正常同步已确认再出现，即使后续处理失败也使旧缺失证明失效，允许单独保守清零而不追加成功轮。dry-run 不持久化该观察、不迁移旧库、不推进轮次／缺失，预览候选不等于删除。一个 source 失败不推进它的缺失依据，也不得借另一源成功执行清理；是否继续其他独立 source 由 Task 明确。配置源根缺失／不可访问／存储离线时不清理；移除 source 配置不清扫其历史归属。

缺失计数不能来自 dry-run、失败、取消或不完整分页。每次删除前，须以已提交的至少三轮不同完整成功缺失证据为依据，再取得独立、当前、可解释的权威不存在确认，并重核可靠归属、精确远端／本地映射、输出边界和文件类型。HTTP／JSON 404 或任意 get 错误本身不足；可采用成功刷新并完整读取可访问父目录后的精确名称确认。父目录也消失时须有可访问祖先的完整逐段证明或等价证据，不能猜测。缓存空结果、刷新失败、权限或离线均保留；采用机制须有固定隔离 OpenList 版本／驱动的真实语义实证，合成夹具不替代。

### 最终 Get 与列表证明的边界（2026-10-18 A 裁定）

用户认可采用完整刷新列表作为缺失证据。[API 文档](https://fox.oplist.org/364155733e0)确实列出 `/api/fs/get` 的 404 未找到；这不保证所有版本／驱动对真实缺失都返回 404。固定 v4.2.7 的既有隔离证据显示真实缺失返回 HTTP 200、应用码 500，[固定源码](https://github.com/OpenListTeam/OpenList/blob/3b28270a4066ea52943a69ecddd850d83f7e8bdc/server/handles/fsread.go)也将 `fs.Get` 错误统一转为应用码 500，不能从该码区分缺失与驱动错误。

本 Slice 采用以下确认边界；这是对最终诊断请求的有限例外，不将 API 错误升级为不存在证明：

1. 当前配置源根须成功确认为可访问的真实存储目录；用于证明的目录链均须验证真实目录锚点、成功刷新并完整读取全部分页，精确名称缺失才形成列表证明。中间目录缺失只可经源内已验证祖先的同等证据推导其后路径缺失。虚拟挂载、可见性过滤或列表矛盾不得产生证明。
2. 最终目标 Get 保留为可见性／矛盾探测。成功读取目标与此前名称缺失矛盾，返回无法确认；不能跳过此探测来规避隐藏项反例。权限拒绝同样返回无法确认。
3. 仅在第 1 项证明已独立成立、没有已观察到的权限／虚拟视图／矛盾，且请求返回后 context 仍有效时，允许最终目标 Get 的 **HTTP 200、完整有效错误信封、应用码 500** 不否决列表证明。此结果不提供任何缺失证据；若没有完整列表证明，结论仍是无法确认。不得依赖自由文本 message／Detail 或数字子串识别“文件不存在”。该例外须由固定版本／驱动实证及故障反例支撑，不自动推广到其他错误码、响应形状或全部驱动。
4. 最终目标 Get 的取消／deadline、传输／读取失败、超限、非成功 HTTP（含 404／403／500）、畸形／不完整信封、无效成功 payload，以及其他未明确允许的应用错误（含应用码 404／403）均否决本次确认。只拥有 `*APIError` 类型或两个数字字段并不足以证明收到完整有效错误信封；实现须保留足够结构化分类信息。
5. 源根／祖先锚点 Get 和任何 ListFresh 的错误仍一律使确认无法完成，包含 HTTP 200、应用码 500；不得套用最终目标探测例外或退回缓存列表。所有返回路径保留取消检查、深度／请求／目录限额与调用间隔离。三轮资格、归属、本地边界及 dry-run 规则不变。

验收须分别覆盖“完整列表后真实缺失＋允许的最终 500”“缺少列表证明＋相同 500”“锚点／列表失败＋相同 500”，以及最终探测阶段的超时／取消／传输／HTTP／信封错误、隐藏项与虚拟挂载反例。旧证据不代表修正后的实现通过；完整 T4 与固定隔离真实服务须按新候选重跑。

### 刷新频率与网盘请求负担（2026-10-18 用户约束）

用户指出频繁强制刷新会增加网盘风控风险。普通生成／更新扫描继续使用 `refresh:false`，利用 OpenList 缓存；缓存未命中／到期仍可能回源，不承诺零网盘请求。三轮完整缺失观察不要求三次全库强制刷新；这些观察只形成候选资格，缓存结果不能替代删除前独立的当前刷新证明。缓存仍显示旧对象时保留，待后续正常同步收敛。

强制刷新仅用于达到所需已提交缺失轮数、且本地归属／映射／边界初筛合格的清理候选，范围限于其必要父目录／祖先链，不附带刷新整个源。候选按目录／共同祖先组织有界批次，同一批候选共享本次完整读取所得的不可变目录证明，不能逐文件重复刷新相同目录；证明不跨轮持久化、不从旧扫描或 dry-run 借用，批次结束释放。逐目标的权限／矛盾探测仍保留；探测与锚点 Get 可能产生的回源也计入请求负担，不能只限制显式 refresh。

确认请求须有可调的请求间隔、并发及每轮工作预算，避免突发刷新与密集重试；具体参数、支持范围及接入方式由 B 依据固定服务／驱动实测规划，不虚构全网盘通用的安全频率。预算／冷却未允许确认的候选保留并报告延期，不伪造成功确认、不因延期新增持久缺失证明；若当前完整轮本身有效，仍依既有完整轮规则处理。限流／风控拒绝或其他请求失败停止受影响的确认工作，不能继续重试凑出缺失结论。

分页策略须避免“每页强制重新取得整份目录”的请求放大；允许以有界单次完整响应或经实证可验证来源新鲜性的其他读取方式取得完整列表，仍须满足响应／目录限额、精确名称、总数／重复名校验及可见性边界。不得未经证明就改成第一页刷新、后续页任意缓存；若固定版本／驱动无法在请求预算内提供可靠完整证明，则保留并报告无法确认，不退回高频刷新或降低删除安全条件。

这将目录复用和请求负担从原延期优化收为 Slice 2 必要约束，不扩展成规模吞吐承诺。B 须协调 Task 2.1 的每页刷新、单路径独立确认／批内证明复用、配置非目标及测试计划，决定当前 Task 调整或重规划。验收需分别记录客户端请求、强制刷新流程及可观测的驱动回源次数，覆盖同目录多候选、共同祖先、宽目录分页、预算延期与限流失败；不能只看 HTTP 调用数推断网盘实际请求数。

### 持久证据与恢复

Slice 1 旧库保留归属，不把旧 round／created_round 追认为缺失证明。精确远端映射可通过后续观察补齐；历史已缺失且无法可靠补齐的记录保留并报告，不从 .strm 猜原扩展名、不自动再认领。媒体扩展名变化映射到同一输出目标时，按 URL 比较处理该目标的出现／更新；同轮不同媒体映射同一目标则失败。

不消费尚未完成的本轮作为删除证据。可在后续真实同步消费已提交证据；稳定、安全条件具备且确认预算／冷却允许时，至迟在形成所需完整缺失证明后的下一次成功同步收敛。受预算限制可延期并报告，在有限稳定候选集与可用预算下持续运行须逐步处理，不能永久饿死候选。清理错误不得留下失败轮新增的缺失依据。多个文件不承诺全源原子回滚；每项均先满足证据与检查，后续删除／目录 sync／DB 失败时停止该源后续清理，报告已完成操作，重启重新核实并收敛剩余文件／归属记录。远端再出现则重新生成；孤儿记录不授权删除未知文件，不能要求管理员手改计数或盲删残留。
