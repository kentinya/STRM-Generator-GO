开发准备基线已交付：中文需求／架构／合同、API 夹具、质量检查、CI、固定 Go 工具链与交接。用户随后要求激活 Slice 1「安全的单轮生成闭环」，当前以其 ACTIVE 合同限定范围；当前实施单元见 [TASK.md](../TASK.md)。Task 1.1 的 sync／dry-run 基线有历史 B PASS；Task 1.2 最新候选 `d0e2bac` 仍 FIX REQUIRED，尚未按澄清合同重新验收。F-14 绑定根目录游标共享导致恢复漏检，与外部写者无关，须修正；正常更新／中断后重试也须按现有比较规则收敛。历史 F-10／F-13 与外部注入产生的 F-11 事实保留，但不再自动等同于新范围阻断项，不能换名为 legacy 继续要求抵御任意写者。修正留在同一 Task，不把有二进制或旧场景通过视为验收通过。

产品范围：OpenList list／get 元数据；稳定 `/d/` URL；版本化 STRM；目录镜像；增量比较与原子更新；SQLite 最小归属／轮次；经过完整成功对账的安全清理；单轮互斥、有界目录并发；手动／预览／定时；Linux amd64／arm64 容器与二进制；最终一致性和分层验收。

2026-10-18 用户授权 A，并澄清只要求正常单写者使用与最终一致性，详见需求 SW-1..SW-6。生成器负责写入、消费者只读，多生成器共享锁资源；不建设额外权限安全系统，不强制 UID／mode 检查、消费者 OS 拒写实验或任意外部残留永久冲突。不承诺无损抵御绕过锁的任意外部干预，也不把所有偏差判作必须重建状态。真正未归属保护、原协议／比较规则／SQLite 边界不变；F-14、正常失败恢复与完整 T4 仍待完成，不修改生产权限或服务。

排除：实时一致性保证、独立发现或媒体版本状态机、下载媒体计算哈希、生成签名临时链接、ffprobe／转码、修改 Jellyfin 数据库或代理、触发插件内部任务、三组件自动串行编排、保留移动后的 Jellyfin Item ID／媒体流保证。

方案中的十万至百万规模是目标；512 MB 是初始压测限制，尚无内存或吞吐承诺。真实数据源配置、访问身份、挂载的 `/d/` 无签名可用性、媒体扩展名与 SQLite／YAML 依赖版本，应在相应 Task 用实证确定，不自动借用生产环境。
