1. 管理员填写 API 地址、稳定公开地址、环境变量 token、源与专用输出根，先预览。无效配置、输出重叠、冲突或权限不足时明确失败，不能开始部分清理。
2. 首轮同步读取目录／元数据，在对应目录原子创建 STRM，并建立最小归属。日志摘要列新增／更新／跳过／异常／失败，不显示凭证。原有未归属文件保留并提示冲突。
3. 重复运行不改未变化文件；URL 变化更新，哈希相同但 Size 异常保留文件并报告。元数据不可比时说明限制。
4. 清理默认关闭，启用后，正常对账未观察到的已拥有路径在源根可读取时用 Get 判断，目标未读到计一次缺失；不再区分相同未读到响应的其他原因。默认连续三次完整轮缺失且删除前按同规则重核后，才清理自己的 STRM。源根读取不到则保留并冻结计数；目标再出现清零。移动的新路径按已有生成规则交付，旧路径随后退出，短期可同时存在，Jellyfin Item ID／媒体流不保证延续。
5. 所有列表请求均关闭强制刷新。列表失败／分页不全、整轮停止或必要本地写入失败不新增缺失次数；目标 Get 未读到则是用户明确接受的缺失观察，即使源于权限／驱动／缓存等原因也不另设保留门槛。清理本地失败停止后续删除，恢复后正常重试，不要求手工改计数。源配置被移除时保留历史归属。
6. dry-run 展示预计新增、更新和符合当前持久证据的清理候选，不把候选称作已删除，不写库／文件／计数或迁移旧库；下一次真正运行重新获取事实，不能借用本次预览凑足缺失轮。
7. Slice 3 的 serve 支持首轮立即执行和按间隔定时，与手动使用共同互斥入口；重复运行给出忙碌／跳过的明确结果，不重叠，停止不提交不完整轮。

2026-10-18 用户最终选择简化 Get 规则及所有列表 refresh:false，撤回之前的定向强刷、权威列表证明与请求预算方案。缓存可能使变化延迟反映，Get 也不保证零后端请求；本规则接受“源根存在但目标因其他原因未读到”也会累计删除次数。准确边界见[需求](requirements.md#简化删除判定2026-10-18-用户最终决定)，Task 2.1 已按此规则完成实现及独立审查，计数／删除／预览由当前 Task 2.2 接通。

生成完成后由管理员分别安排 Jellyfin 库扫描与插件原生检查；三者没有自动串行保证。生成器成功仅表示本地同步结果，不能显示“播放已验证”。插件的首次信任、权限、探测成功后提交历史指纹由插件自己处理。Slice 3 的 Docker 运行包只验证隔离挂载、停止和状态说明，不替代真实播放或生产部署验收。

数据库丢失／不可写时停止有风险的写入和清理，保留输出并报告恢复路径；不能盲目认领整个输出目录。发布前为备份、恢复、数据库兼容、锁与临时文件恢复提供实测说明。真实 token 只放本地忽略文件或环境变量，不能出现在错误正文中。

Slice 1 旧库保留归属，历史成功轮不能充当缺失轮。后续正常观察可补齐清理所需的精确远端映射；已经缺失且映射无法可靠补齐的旧记录保留并报告，不猜原媒体扩展名。清理发生本地失败或停止时，报告已完成与保留项，重试重新确认后继续；多个文件不承诺全源原子回滚，不要求管理员伪造轮次或盲删残留。

## 正常写入、重试与维护

正常部署由生成器写输出／暂存／状态，Jellyfin／插件等消费者只读；所有接触同一输出的生成器共享同一锁对象。避免外部程序同时改写该树，可按环境选用专用身份或只读挂载，但本 Slice 不要求权限管理功能或额外身份隔离验收。远端 OpenList 不必停止变化。

远端扫描期间变化、暂时写入失败或已拥有可再生成 STRM 的可识别偏差，依现有比较规则在输入稳定、服务和存储恢复后的成功同步中纠正；正常重试不一律要求新输出／新数据库，也不承诺下一次必然成功。没有可比元数据时沿用既有保守规则，不凭空识别每种错误内容。

真正未归属的文件、数据库丢失后无从确认归属的文件或明确路径／类型冲突仍保留并报告，不因声明单写者就认领。需要人工维护时建议先停生成器并备份；遇到无法解释的残留先保留和排查，不盲删暂存或伪造归属。不承诺阻止或无损逆转任意绕过锁的外部修改，但这也不是要求正常生成器中断永久报冲突。
