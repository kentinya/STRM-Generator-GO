# 用户旅程与恢复

这是目标体验。仓库已有 Task 1.1 的 `strmgen sync`／`sync --dry-run` 实现（经 B 审查 PASS）和 Task 1.2 的内容更新候选；后者最新候选 `d0e2bac` 经 B 独立复审仍为 FIX REQUIRED，须修正跨多次运行保留外部 STRM 冲突证据、检查后清理／发布竞态，以及绑定根目录游标共享造成的多文件恢复漏检。当前 Task／B 审查状态以 [TASK.md](../TASK.md) 为准。Task 1.1／1.2 不实现清理或定时；以下描述不是当前已验收能力清单。

1. 管理员填写 API 地址、稳定公开地址、环境变量 token、源与专用输出根，先预览。无效配置、输出重叠、冲突或权限不足时明确失败，不能开始部分清理。
2. 首轮同步读取目录／元数据，在对应目录原子创建 STRM，并建立最小归属。日志摘要列新增／更新／跳过／异常／失败，不显示凭证。原有未归属文件保留并提示冲突。
3. 重复运行不改未变化文件；URL 变化更新，哈希相同但 Size 异常保留文件并报告。元数据不可比时说明限制。
4. 远端移动时先出现新路径，旧路径经过两轮完整成功缺失及再次确认后才清理。因此短期可能同时存在新旧路径；这属于最终一致性。Jellyfin 可能重新入库，Item ID 和既有媒体流不保证延续。
5. OpenList 故障、部分分页失败、停止或本地写入错误时保留旧 STRM，不推进缺失清理。恢复服务后重新运行；不需要人工伪造成功轮次。
6. dry-run 展示预计新增、更新和符合当前证据的清理候选，不写库／文件／计数；下一次真正运行重新获取事实。
7. 后续 serve 支持定时，与手动使用共同互斥入口；重复运行给出忙碌／跳过的明确结果，不重叠。

生成完成后由管理员分别安排 Jellyfin 库扫描与插件原生检查；三者没有自动串行保证。生成器成功仅表示本地同步结果，不能显示“播放已验证”。插件的首次信任、权限、探测成功后提交历史指纹由插件自己处理。

数据库丢失／不可写时停止有风险的写入和清理，保留输出并报告恢复路径；不能盲目认领整个输出目录。发布前为备份、恢复、数据库兼容、锁与临时文件恢复提供实测说明。真实 token 只放本地忽略文件或环境变量，不能出现在错误正文中。

## 单写者部署与维护

用户于 2026-10-18 授权 A 限制外部写者，具体要求为需求 SW-1..SW-6：管理员为生成器配置专用写入身份和输出／状态范围，Jellyfin／插件等消费者只读，不运行会改写、重命名或删除该树的其他工具。所有接触同一输出的生成器必须共享同一锁对象，不以各容器私有 /tmp 的同名文件代替；不要求远端 OpenList 停止变化。

权限、身份、ACL、祖先目录和挂载隔离由管理员保证。程序应拒绝能直接检查出的属主／组或其他可写条件，但不会自动收紧权限，也不能承诺识别同 UID／root 的绕过操作。需要人工维护时先停全部生成器并保存输出、DB 和残留；修改过已拥有目标／状态后不能直接沿用旧归属重新运行。遇到不明恢复冲突先保留全部证据，不盲删暂存；当前没有通用再认领功能，重新生成应由管理员确认并选择新的隔离空输出与新状态。

这不是当前部署已受保护或 Task 1.2 已通过的声明。当前仍需 Developer 完成已知条件校验、独立有界恢复扫描、未知残留的重复冲突保护和新合同验证；B 复审、真实 OpenList 与固定插件解析仍独立进行。
