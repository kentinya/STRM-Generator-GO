### 插件比较输入与判据

详细矩阵见 [D-01..08](../docs/test-matrix.md#slice-4-实际插件决策矩阵)。固定源码决策器
先看主媒体流／原生 URL，再看历史指纹／SHA-1／Size，不能用 MissingPrimaryStream 或
FirstTrust 假装验证了 SHA-1／Size 比较。比较基准须有正常原生检查和明确复用记录，
每行前重新建立并核对基准，优先复用同一路径／item。移动允许新 item，不要求保留媒体流。

- D-01／02：完全不变、远端仅 Modified 变化各留一次实际复用；STRM 不添加 Modified。
- D-03：同批本地原件算真实 SHA-1，测试副本只改 Size 并标注异常；预期 Sha1Matches 复用。
- D-04：同 URL 切换到同批另一实际内容，副本写其真实 SHA-1／实际 Size；预期探测启动。
- D-05：同内容换另一个稳定可访问 URL；旧基准先匹配原生地址，变更后预期探测。
  若观察 NativeUrlMismatch，须证明由本次 URL 变化引起，不能用无关地址／主流缺失冒充哈希比较。
- D-06／07／08：明确哪侧无有效 SHA-1，分别构造有效 Size 不同、相同和信息不足；
  不同内容的 Size／服务字节真实匹配；预期探测、Unchanged 复用、InsufficientFingerprint 复用。

使用锁定插件已有日志：`Native STRM probe started` 或明确需要探测记录为探测；
`reused saved media information` 且 reason 匹配为不探测。只按正确 item/source 在当次窗口
核对；没有日志或只有计划任务完成均为未完成。探测结果是否成功不作该行门槛，后续行
若缺基准须先恢复建立，不以失败结果当作可比较历史。不得调用内部方法或改数据库造历史。
